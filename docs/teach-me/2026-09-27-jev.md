# Learning note: how to use Jev (TypeSafe)

Date: 2026-09-27. Source: live docs at https://docs.typesafe.ai (fetched this session).

## Part 1: What Jev is

- **Jev**: TypeSafe's first "System One" model. It takes text plus a question and returns a typed answer with a probability. It never generates text, code, or reasoning. Evidence: `concepts/system-one.md`.
- **Input limit**: text only (strings, JSON objects, arrays). No images or audio.
- **Use case in this fleet**: tier routing. State = task description. Question = Choice over `flash` / `workhorse` / `flagship` / `ultra` with a one-line rubric per tier. Low confidence routes to a person, not up a tier. Ties to the ladder in memory `fleet-capability-tiers`.
- **Can it route well?** Unknown. TypeSafe publishes no routing benchmark. Known weak spots (`model-jaggedness/jev-1.13.md`, reviewed 2026-09-17): literal reading, multi-hop indirection, large irrelevant state, math/counting/dates.
- **Routing design that fits those limits**: do not ask "which tier?" directly. Ask several literal Nouls about the task text (design decision needed? single file named? done-condition stated?). Map answers to a tier with rules in code.
- **Test set**: past tasks with a verified per-tier PASS/FAIL outcome. Checked 2026-09-27: no such log exists. `.workerbees/ledger.jsonl` has 4 rows (2 dispatches), a task category word only, no verdict. `~/.codex-bridge/usage.db` has tokens and model only. rl-quadmesh logs: 20 runs with exit codes (16 exit=0), and an exit code is not a verified result. To test Jev routing, the fleet must first record task text, tier, and verified PASS/FAIL per dispatch.
- **General pattern**: use Jev where code needs judgment about language but the answer fits a fixed set of values. It replaces an LLM call plus the parsing after it.

## Part 2: The three question types

Evidence: `primitives.md`.

- **Noul**: yes/no. Returns `noul` = probability of yes. No `confidence` field. Code: `if`.
- **Choice**: one option from an unordered set (max 255). Returns `choice`, `probabilities`, `confidence`. Code: `switch`. Always add a `none` option, because answers are limited to the options given.
- **Score**: position on ordered levels you describe (2 to 10). Returns `score` (can fall between levels), `legend`, `probabilities`, `confidence`. Code: threshold.
- **Trap**: Noul 0.5 means "yes and no equally likely", not "medium". For degree, use Score.
- **Question ID** is for code only and is never sent to the model. Write the full question in `instructions`.

## Part 3: How one call looks

Evidence: `concepts/state.md`, `api.md`, `sdk/python.md`.

- **Call** = `state` (text to judge) + `questions` (map of ID to question) + `model` (`jev-latest`). HTTP: `POST https://api.typesafe.ai/v1/systemone`. Python: `pip install typesafe-sdk`, key in `TYPESAFE_API_KEY`.
- **State**: prefer a JSON object with named fields. Point questions at fields with backticked paths, for example `` `task` ``.
- **Batch questions**: all questions on one state go in one call. They run in parallel and cost only their input tokens.
- **Independence**: no answer sees another. Combine answers in code.
- **Routing sketch** (untested, no key): Nouls `done_stated`, `needs_design` + Choice `kind`, then `if` rules pick the tier. Cutoffs such as 0.7 are placeholders until tested.
- **Try without a key?** No free path at TypeSafe: `console.typesafe.ai` and an unauthenticated `POST /v1/systemone` both return 403 (checked 2026-09-27). Pricing: $0.042 per million input tokens, output free, 64k context (`models.md`).

On 2026-09-27 its endpoint list was empty and its price showed `-1`. It routes among OpenRouter models, not this fleet's Claude or Codex subscriptions.

## Part 4: Confidence

Evidence: `confidence.md`.

- **confidence**: 0 to 1, on Choice and Score answers only. It measures how peaked the probability distribution is. Noul has none; read the probability directly (near 0.5 = unsure).
- **Three bands**: high = act; medium = confirm or flag; low = do not act, route to a person or a stronger model.
- **Thresholds scale with stakes**: docs example uses 0.5 as the floor and 0.9 for a risky action. Tune on own data.
- **Confidence vs probability**: probability = chance of one option. Confidence = how clear the winner is given the option count. Top 0.6 over 2 options gives confidence 0.2; top 0.6 over 5 options gives 0.5 (docs demo approximation `(n × top − 1) / (n − 1)`). Threshold on `confidence`, not top probability.
- **Calibration**: claimed, not shown. Trained with RLCD to give honest probabilities (`introduction/machine-learning-primer.md`). No published reliability curve or calibration score found. Holds only across groups of predictions, never for one answer (`concepts/system-one.md`). `confidence` is not "chance of being right". To check: group own past answers by probability and count hits. Needs the missing outcome log.
- **Setting thresholds**: (1) 100 to 200 cases with known answers; (2) run Jev, record confidence and correct/wrong; (3) per cutoff, read coverage (share handled alone) vs accuracy (share right when acting); (4) pick the lowest cutoff whose accuracy meets the bar for that action's stakes. Below cutoff goes to a person or a stronger model.
- **Building the test set** (none needs a Jev key): A = log task text + tier + verified PASS/FAIL per dispatch from now on (slow, best); B = hand-label the ~37 past prompts (17 in `at_route_answers.log`, 20 rl-quadmesh runs); C = write ~100 task descriptions and label the right tier. Recommended: C now, then A. B is weak: 13 of the 17 `at_route_answers.log` prompts are probes or chat ("say ok", "pong"), 4 are real tasks, and the 20 rl-quadmesh runs are one campaign. Keep those 4 inside C. The same set can score Haiku routing today. Open check: whether ledger code can store a verdict (tests mention verdicts; the 4 live rows have none).
- **Versioning**: pin `jev-1.13.0`, not `jev-latest`, once thresholds are tuned. Re-run the test set before moving to a new version (`models.md`).
- **Fleet reading**: low routing confidence means the task text is unclear. Ask for a clearer task. Do not escalate to ultra on it.

## Part 5: Fit and decision

- **Good fits**: literal yes/no features for tier routing (code picks the tier); flagging delegate reports that claim success without quoted output (send only the summary, since long state hurts accuracy).
- **Poor fits**: generation, coding, reasoning; counting, math, dates.
- **Blockers**: no account (signups closed 2026-09-22); no test set. Cost is not a blocker: $0.042 per million input tokens, $5 credit. The "spend nothing" rule is scoped to OpenRouter; whether it covers TypeSafe direct is still the operator's call.
- **Decision (2026-09-27)**: watch + build test set. Keep the watcher (signup + jev-router). Build a ~100-case routing test set (option C, keep the 4 real `at_route_answers.log` tasks), score Haiku routing on it now, and drop Jev in when access opens.
